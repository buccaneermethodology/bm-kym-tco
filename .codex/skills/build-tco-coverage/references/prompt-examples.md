# 用户提示词示例

- 初始TCO：“基于这个KYM候选建立TCO，先讨论用途和TP划分。按TP→Mc→M展开，共享M只维护一份；每M用大白话写TSP、流程图、IPO，复杂分支给例子，必要时给Modeling/UI图。交付固定模板Markdown和HTML。”
- 简短默认：“用这个KYM生成TCO。”复用已有目的/来源，必要时引导；默认仍执行行为拆分、映射和阅读质量流程。
- 直接生成：“不先交流，按当前KYM直接出候选；未确认切片单列建议，不编造Target authority；没有实现证据就保留未评估。”
- 当前覆盖：“按指定代码版本盘点每M应证明什么、已有证据实际证明什么、推进目标还差什么；先核旧证据是否适用，不默认新增测试。”
- 任务进展：“基于既有TCO补当前任务贡献，原始义务和基线不变，区分任务关闭、能力覆盖、运行证据；同时给进度companion和详细reader。”
- 证据不足：“先给需求/设计展开，Coverage保持N/A，逐行为列未来观察和最小取证建议，不把未知写成未实现。”
- 切片比较：“比较这两种候选TP划分的读者价值、共享能力和独立验收边界，不按Session数量机械划分，不自动批准任何一种。”
- 增量更新：“只更新受影响能力与证据，保留共享M ID和历史Profile；给映射、行为及Coverage变化，不改未影响部分。”

交互优先复用上下文，用户可以随时选择直接一稿。阅读生成不自动授权产品改动、测试扩建或Goal恢复。

没有明确TP且不交流：“先给KYM详细reader和TP/TCO组织建议，标明为何还未形成合法TCO模型，不编造Profile来凑格式；确认后再走完整TCO包。”

## 按E／C／Q查看进展

- 首次盘点：“基于这个版本的TCO和现有Session、代码、验证及问题记录，让我看每个M已经做过什么、功能实现到多少、当前质量怎样。C按功能实现覆盖估计，TP运行目标另外说明；不清楚的保留未知，数字都能追到来源。”
- Session后更新：“核对本Session的实际贡献，列它推进的M和原始业务要求；重算E／C／Q并与上一快照比较。同一Session全局只计一次，新增要求导致的分母变化单列；没有推进也如实写。”
- 安排下一步：“先列每M最影响判断的缺口，核对已有证据是否仍适用，再提出最小动作。多M可共用的工作只给一份候选Session卡，说明输入、产物和验收，不自动执行。”
- 只有需求：“先整理每M的业务要求、职责和验收点。Session未整理就写尚未整理，功能实现和质量未知，不填0%或用设计完成代替功能实现。”
- 发现回归：“保留历史快照，指出当前版本受影响的M与要求；若缺陷否定功能实现程度，C随之回退，旧通过证据不能自动沿用。其他无关M不跟随变更。”
- 共享能力／目标比较：“在两个TP中复用同一个M定义，显示各自要求和运行目标。不要平均多个M百分比；共享原始要求按明确的验收组合汇总，组合未知就保留全局未知。”

简短调用也应沿用上述默认口径；这些例子帮助指定输入与关注点，不要求用户在prompt中重写计算合同。

## 默认无需重复要求详细程度

“用这个KYM生成TCO”也默认全量详细TSP、每步输入/动作/结果、传统SVG与树形/表格；以下提示只指定关注点，不改变默认完整性。

- 快速一稿：“直接用当前来源生成候选，不先互动。具体未知单列，让我先看全貌。”
- 业务评审：“给业务负责人审阅，先把目的和TP划分中真正缺的信息问清楚；已有答案复用。”
- 老稿更新：“沿用既有TP和M身份，补到新版完整阅读；来源不足的步骤明确待确认，原始数据和历史保留。”
- 只读历史：“只解释这份旧稿，不重建模型；说明哪些是原稿已有，哪些无法判断。”
- Session后进展：“更新实际贡献、功能实现估计和质量，主页面突出已做工作与下一步；机器历史另存。”
- 来源不足：“根据现有需求完整解释TSP与流程；不能确定的输入、判断或停止条件写具体问题，不编成事实。”

KYM场景只建立KYM及其业务规则阅读展开，不因为这个通用示例而越界生成TCO或Coverage。
