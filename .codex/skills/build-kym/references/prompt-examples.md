# 用户提示词示例

无需用户重复内部校验规则；优先从现有上下文补齐已知信息。以下是目的/范围/组织偏好示例，不作为强制长prompt。

- 新需求并愿意交流：“用build-kym整理这些需求，面向业务和开发。先问我会影响范围和切片的几个问题，再给候选KYM与固定思维导图。”
- 简短默认：“请为这份需求生成KYM。”先判断来源和用途，只询问关键未知，不能因短prompt就生成低质量标签。
- 直接一稿：“不先提问，按现有来源出一稿；推断和缺失内容原位标明，建议切片先列候选，不替我确认。”
- 执行历史：“整理这个Goal截至指定版本的需求全貌与已有贡献，保留原始验收清单，不把任务完成数当产品覆盖率。”
- 仅KYM：“只梳理客户、业务规则和项目边界，不评估实现；用规则语义分组，给必要TSP解释和实例，后续可对应TCO。”
- 迭代：“按这次明确修正更新既有候选，保留此前Profile和来源，显示变化和待确认，不重写历史结论。”
- 信息不足：“请先指出哪些分支缺信息，优先问会改变目标划分的部分；其余可以带假设先写。”
- 未明确TP且不交流：“先交付KYM详细reader和TP/TCO组织建议，保留待确认；不要为满足TCO模型格式捏造正式Profile。”

需要详细TCO时再调用build-tco-coverage，传确切KYM候选与来源边界。已有引导答案复用，不重复盘问。用户要求直接出稿不等于允许编造事实、批准Target或发布。
