# 引导式生成与直接出稿

先从用户请求和现有上下文识别目的，不重复询问已经明确的事实。默认在生成前提供一轮简短引导，最多同时询问三个高价值问题：

- 此次是理解新需求、比较方案、安排可交付切片，还是核对已有工作的覆盖和剩余动作？谁会读？
- 范围、事实截止点、可靠来源及明确排除项是什么？哪些分支缺少会改变判断的信息？
- Target Profile希望按什么业务情境或可独立交付结果划分？说明你的候选划分和依据，让用户选择或修正；不要把Session数、阶段数机械等同TP数。

用户已给足信息时直接复述采用的目的与划分，不强迫再答一轮。信息不清楚时，使用宿主可用的提问工具；先问是否愿意简短交流，并同时提供“直接按现有材料出一稿”。用户选择直接生成或明确要求不提问时，记录mode=direct、status=assumed、假设及就地待确认，继续候选。没有工具答复不能当用户同意；不依赖答复的来源整理可以继续。

交互答案是新来源，按原话/实际轮次采集和绑定；不得伪造回答、将Agent建议写成用户已说、已确认或已批准。用户偏好的阅读组织不等于业务事实。

## 目标与能力

TP表示一种目标情境和达标要求；M为可独立设计/验证的能力，关系是多对多。同一M仅有一份定义，可在多个TP下复用；Mc是共享域分组，不计入能力或要求分母。一个Profile可以合理，但必须说明为何足够，并检查是否需要不同情境/门槛。愿景总览不能替代可判断的详细要求。

canonical Target仍遵守现有显式来源authority门槛。用户仅要求Agent建议切片、尚未确认名称/目标/要求时，在reader detail.intake.proposed_profiles中记录候选及理由，不冒充canonical Target，不纳入Met分母。确认后先按来源流程生成新KYM候选，再交TCO，不让reader改写源模型。

没有合法canonical TP且用户选择直接出稿时，也要立即交付可读的一稿：保留KYM的空Target分支，用KYM-only reader展开业务规则的详细能力/IPO/判断行，在proposed_profiles列TP与TCO组织建议、理由和待确认。既有TCO v4要求至少一个合法Profile，此时不能伪造Profile或空数组TCO模型来声称package就绪；明确本稿是KYM详细稿与TCO组织建议，已有兼容reader可直接渲染。若已有合法TP，仅新增未确认切片留在建议区，继续完整TCO路径。确认后由实际问答来源生成新候选，不靠改摘要或虚构答复补权威。

## 新项目防错顺序

识别用途/必要提问 → 来源与原始义务清单 → 目标情境及候选切片 → KYM语义规则组到共享能力的projection → 先检查已有证据充分、证据混合、未实施三类代表能力（不足三类按实际） → 全量义务与行为完整性 → 结构/表达审计 → 独立语义阅读 → 固定HTML实际阅读检查。

代表样例只验证方法，不能替代全量完整性。不要规定每M固定两条或固定条数，不靠加字数和重复边界过关。先复用适用的证据，确有缺口才提出最小补验；阅读生成不能自动授权新测试、改产品或推进Goal。宿主没有独立review/浏览器时明确未观察边界，不把静态脚本当真人阅读或浏览器验收。
